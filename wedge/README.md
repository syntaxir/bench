# Wedge benchmark

The wedge benchmark compares SyntaxIR with other Go parser generators on grammars the size of a
domain-specific language. Each grammar is written for every tool with the same language and the
same output class, typed values: each tool builds its own values of the grammar during the parse.

It is a separate Go module, so the tools it compares never become dependencies of
`syntaxir.dev/sxir` or of the harness. It requires `syntaxir.dev/sxir`, whose public runtime the
generated SyntaxIR parsers import, from a SyntaxIR checkout that a `go.work` names.

## Grammars

| Grammar | Language | SyntaxIR source |
|:--|:--|:--|
| `calc` | Numbers, `+ -` below `* / %`, prefix `- +` below a right-associative `^` whose exponent may be prefixed, parentheses | `grammars/calc.sxir` |
| `filter` | Comparisons of dotted fields with literals, membership in a list, `!`, `&&` and `\|\|` | `grammars/filter.sxir` |
| `json` | RFC 8259; strings and numbers keep their text | `grammars/json.sxir` |

`grammars/calc.sxir` and `grammars/json.sxir` are copies of SyntaxIR's `examples/calculator/calc.sxir`
and `testdata/grammars/json/json.sxir`, so that every SyntaxIR version is measured on the same
grammars. The other tools' versions are in `pigeon/*/*.peg` and `participle/*/*.go`.

## Tools

| Tool | Version | Form | License |
|:--|:--|:--|:--|
| SyntaxIR (`sxir`) | The checkout that `go.work` names | Generated Go with limit controls (the default), and generated with `-no-limits` (`sxir_nolimits`) | Apache-2.0 |
| [pigeon](https://github.com/mna/pigeon) | v1.3.0 | Generated Go, with `-optimize-parser -optimize-basic-latin` | BSD-3-Clause |
| [participle](https://github.com/alecthomas/participle) | v2.1.4 | Struct grammars, a simple lexer with whitespace elided | MIT |

The versions are pinned in `go.mod`. The configuration of each tool is open to review by its
maintainers.

## Inputs

Each grammar has a short input of at most 1 KB, the latency case, and a long one of at most 128 KB,
the throughput case. Both come from seeded generators: `ArithInput` and `JSONInput`, copies of the
generators of SyntaxIR's benchmark inputs, and `FilterInput`.

## Running

```bash
go work init . /path/to/syntaxir                # resolve syntaxir.dev/sxir to a checkout,
go work edit -replace syntaxir.dev/sxir@v0.0.0=/path/to/syntaxir # including the version go.mod requires
go generate                                     # regenerate the parsers
go test -run 'TestEquivalence|TestInputs' .     # the tools agree on acceptance and values
go test -run '^$' -bench BenchmarkWedge .       # time, bytes and allocations per parse
```

`TestEquivalence` runs a hand-written corpus of valid and invalid inputs and the generated inputs
through every parser. Each valid input must be accepted by every parser, with values equal to
SyntaxIR's in a canonical form. Each invalid input must be rejected by every parser. A time is
comparable only when this test passes.

The committed SyntaxIR parsers were generated by the SyntaxIR commit that the harness was imported
with; `go generate` rewrites them for the checkout that `go.work` names. `go run ./cmd/timed -parts
wedge` in the root of this repository measures the wedge by the [timed measurement
method](https://github.com/syntaxir/syntaxir/blob/main/docs/performance.md#timed-measurement-method),
with the parsers of each arm generated by that arm's `sxir`.
